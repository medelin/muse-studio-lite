## 2026-10-29 — your own assistant: personal access tokens, `/api/v1` and remote `/mcp`

- **Tokens** (`studio/api_tokens.py`): made and revoked by the signed-in owner on `/account` ("Assistants & API", `account_assistants.html`, strings in `studio/ui/i18n_assistants.py`, EN/PL). Value `msl_tok_<id>_<secret>` shown once; stored as HMAC-SHA256 under a key derived from the ledger key; scopes `read` and `read draft` only (a `CHECK` constraint, no `sign` scope exists); expiry 7 / 30 (default) / 90 days, last-used time, label, at most 10 live per account; a disabled or deleted account's tokens stop at once. New tables `api_tokens`, `api_briefs` (one self-contained step at the end of `db.init`).
- **Operations** (`studio/assistants.py`), one entry for both transports with scope check, JSON-schema check, per-token rate limits (120 requests, 10 drafting calls a minute) and a `tool_call` receipt per call in the token's own run (`api_<token id>`, agent `api:<label>`, the token id, never its value, transport `http`/`mcp`): `whoami`, `list_briefs`, `read_brief`, `draft_brief` (+ audio upload through Muse Voice Transcribe), `confirm_brief`, `start_run` (the web UI's run path, live models, normal budget; `routes_studio.confirm_and_start` gained `agent` and `untrusted`), `run_status` (plan, copy, image links, reviews, `sign_url`), `pending_approvals`, `campaigns`, `insights`, `leads`, `comments`, `draft_reply` (a pending `reply.post`). Nothing reaches a signature, an executor, a budget, a status or an account. Briefs drafted with a token (and their runs) belong to its account.
- **HTTP** (`studio/routes_api.py`): `/api/v1/…` with `Authorization: Bearer`, OpenAPI at `/api/v1/openapi.json`; cookies never authorize it (the login gate and the sandbox's signed-in-writes rule leave `/api/v1` and `/mcp` to the bearer gate, `auth.is_bearer`).
- **Remote MCP** (`studio/remote_mcp.py`): `/mcp`, Streamable HTTP with the official SDK, stateless with JSON answers, the same tokens checked on every request; every tool description and the server instructions say the assistant cannot sign or launch. No OAuth server (bearer only). The stdio `studio mcp` shares `mcp_server.make_server`.
- **Caddy** (`Caddyfile`, `deploy/Caddyfile`): `/mcp` and `/api/v1` proxied with `flush_interval -1`; the 33 MB voice limit also covers `/api/v1/briefs/voice`.
- Docs: [docs/assistants.md](docs/assistants.md) (Claude Code, Claude Desktop via `mcp-remote`, ChatGPT Actions, curl; what an assistant can and cannot do). Tests: `tests/test_assistants.py` (account forms, draft → confirm → run → pending approval with `sign_url` on the recorded set, reply drafts, OpenAPI, `studio verify`, MCP in memory and over HTTP with the SDK client), `tests/attack/test_assistants.py`.

## 2026-10-29 — Meta's rules explained, not invented: levels by source, what was left out, disapproved ads

Code caps every finding (both models', `policy_net`, `grounding_net`, F1, SAM) by rule and by the channels the copy runs on, and the verdict is derived from the capped levels: tips never raise it. Both reviewer prompts ask for a level and a source.

## 2026-10-29 — SAM 3.1 checks every generated image

- `sam.check` (`studio/muse/sam.py`): after Muse Image draws a placement or carousel card, SAM 3.1 runs on it twice (on a copy at most 768 px): the product concept and `person`. Numbers: matches, product mask area (share of the image), mask box, the image edges it touches, and the **silhouette IoU** against the cut-out — each binary mask cropped to its own bounding box, scaled (aspect kept) into a 64×64 square and centred, IoU = |A∩B|/|A∪B|, the better of the generated mask as drawn and mirrored. Person matches under 0.2 % of the image are ignored. Cost $0.005 per image (two SAM calls), asked of the run budget first.
- Reviewer rules by code, joined to both model reviews like F1: **S1 product fidelity** — product not found or IoU < 0.25 is BLOCK; IoU < 0.5, area outside 5–65 % (story 3–55 %) or touching an edge is WARN; otherwise one info finding with the numbers. **S2 no people** — any person match is WARN (the placement prompt forbids people; SAM 3 is prompted by noun phrases and `person` is a reliable concept, `face` was not added). The review receipt lists the S findings.
- One read-only receipt per image (`tool_call`, `tool: sam.check`, `side_effects: read`): hashes of the image and cut-out in, the overlay's hash out, the numbers and the two model receipts; no pixels. A check that does not run still leaves a receipt: `not_recorded` (a replay set made before the check: the requests carry `metadata.purpose = "sam.check"`, a route of its own, so an old set is detected and never answers them with the cut-out's recording), `skipped` (budget) or `failed` (SAM error, S1 WARN). None of them fails the run.
- UI: each image gets a "Show SAM mask" toggle (`aria-pressed`) over a server-made RGBA overlay `<placement>_mask.png` (product blue, people red, ≤ 512 px, stretched to the image, never wider than it) and a line with the numbers; EN and PL.
