## 2026-10-27 — day 1 fix round (review)

- C1/I5 verify: an approval authorises exactly one write. `external_write` receipts carry `details.approval_id` + `details.action` (`Verified.write_details()`); verify consumes the named approval, requires the same run, content, action and `item_id` and `write.ts - approval.ts <= APPROVAL_TTL_S` (900 s, shared with the server TTL), rejects a second write on the same approval and a nonce that appears in more than one approval; `chain_head == GENESIS` only for the run's first receipt (the server refuses such a pending once the run has grown); server-made approvals that are unsigned, signed by another key or by an unregistered approver authorise nothing; receipts are type-checked after parsing, so hostile lines are reported, never crash; the CLI reports every error as `error:` with exit 2; 30 tests.
- I1/I3 approver keys: `Keys.register` only inserts — a revoked key or one bound to another session is a `KeyConflict` (`POST /api/keys` → 409 `key_conflict`, the browser must generate a new key pair per session); the same live session re-registering its key is a no-op; `verify_and_consume(..., session_id=...)` requires the key to belong to the caller's session (`wrong_session`, 403); 7 tests.
- C1 follow-up (security review): the grant also binds `item_id` — an approval for item A no longer justifies a write to item B with identical content (`write_details()` emits `item_id`; a write without it is rejected); 2 tests.
- I4 receipts: every text field of the public export is covered — `tier_reason` is redacted (e-mail/phone), `run_id`/`agent` must be opaque ids and `model`/`provider`/`tier` opaque or empty (`ValueError` otherwise), on top of the redacted `details`; the receipt table shows `tier_reason` as an escaped tooltip; 17 tests.
- I4 follow-up (review: no fail-open): `Ledger.validate_ids` runs at the start of the Muse client call, before any I/O, so a bad caller id sends no request; values reported by the server are never rejected after the fact — `normalize_id` keeps an opaque response `model` and otherwise stores `unrecognized` plus `details.reported_model_sha256`, so a receipt is always written; 4 tests.
- I2 + security review, login limiter: the global judge-account budget counts only completed attempts (`settle` runs after the body is read and compared, with no `await` in between), so in-flight requests cannot use it up; the login body must arrive within 5 s (408 `body_timeout`, prefix attempt stays counted); 20 failures in 5 min from any addresses pause the account for `5 s * 2**(strikes-1)`, capped at 60 s, strikes forgotten after 15 min quiet — a slow global rate limit instead of the earlier up-to-8.5 h lockout; a paused result is refused and not counted; 5 tests (cap under a sustained storm from fresh prefixes, decay, slow bodies do not consume the budget).
- Limiter follow-up (review ruling: availability over lockout): the capped lock stays; the password carries the brute-force load — `Settings` refuses to start when `JUDGE_PASSWORD` is shorter than 20 characters, has fewer than 3 character classes or fewer than 10 distinct characters (`.env.example` shows the `secrets.token_urlsafe(24)` generator); a 24 h failure budget (hour buckets) logs one loud `studio.login` warning above 500 failures without locking (metric via `LoginLimiter.failures_24h()`, not public); 9 tests.
- Public GETs (review): `/healthz` returns only `{ok, read_only}`; pages show `seq` through the read-only `Ledger.seq()`; the signed manifest is signed once per `seq` and reused, so `/api/ledger-manifest`, `/` and `/healthz` neither change `seq` nor sign a new manifest per request (a write produces the next one); 2 tests.
- I6 budget: durable and reserved — `Budget.from_ledger` rebuilds today's (UTC) spend from `SUM(cost_usd)` of the day's `model_call` receipts, and `MuseClient.from_settings` uses it, so a restart no longer resets the cap; each call reserves a worst-case estimate under the lock before it is sent (input ~3 chars/token, flat per image, output at its cap or 8192) and settles it with the real cost, so concurrent calls cannot all pass a check and overspend; a malformed success body records the usage it reports (tokens + cost in the error receipt), an HTTP error releases the reservation, a network error/abort charges the estimate (`cost_basis: estimate`) since it may have been billed; 11 tests.
- Minor: vision cassette re-recorded on a 256×256 solid red PNG (`scripts/make_swatch.py`, stdlib only; the 16 px swatch had been read as "grey") and the test now asserts the answer is red; `parallel_tool_calls` (default true) is sent with tools on Responses and Chat (spec §2.3), new cassette `spark_parallel_tools` shows the API accepts it (that call hit its output cap, so it is not evidence of parallel calls themselves); unverified `muse-spark-1.1`/`1.2` prices removed (unlisted models are refused); `smoke-live` honours `STUDIO_READ_ONLY`; README explains that `verify --server` is trust-on-first-use and recommends pinning `ledger.pub` and keeping `--min-seq` out of band; `.pre-commit-config.yaml` (gitleaks pinned as in CI, ruff, mypy, pytest); `docs/build-log/` for Muse Code session exports of M tasks; 2 real Model API calls ($0.0028); 10 tests.
