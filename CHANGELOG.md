# Changelog

## 2026-10-27 — day 1 fix round (review)

- C1/I5 verify: an approval authorises exactly one write. `external_write` receipts carry `details.approval_id` + `details.action` (`Verified.write_details()`); verify consumes the named approval, requires the same run, content and action and `write.ts - approval.ts <= APPROVAL_TTL_S` (900 s, shared with the server TTL), rejects a second write on the same approval and a nonce that appears in more than one approval; `chain_head == GENESIS` only for the run's first receipt (the server refuses such a pending once the run has grown); server-made approvals that are unsigned, signed by another key or by an unregistered approver authorise nothing; receipts are type-checked after parsing, so hostile lines are reported, never crash; the CLI reports every error as `error:` with exit 2; 30 tests.
- I1/I3 approver keys: `Keys.register` only inserts — a revoked key or one bound to another session is a `KeyConflict` (`POST /api/keys` → 409 `key_conflict`, the browser must generate a new key pair per session); the same live session re-registering its key is a no-op; `verify_and_consume(..., session_id=...)` requires the key to belong to the caller's session (`wrong_session`, 403); 7 tests.
- I2 + security review, login limiter: the global judge-account budget counts only completed attempts (`settle` runs after the body is read and compared, with no `await` in between), so in-flight requests cannot use it up; the login body must arrive within 5 s (408 `body_timeout`, prefix attempt stays counted); 20 failures in 5 min from any addresses pause the account for `5 s * 2**(strikes-1)`, capped at 60 s, strikes forgotten after 15 min quiet — a slow global rate limit instead of the earlier up-to-8.5 h lockout; a paused result is refused and not counted; 5 tests (cap under a sustained storm from fresh prefixes, decay, slow bodies do not consume the budget).

## 2026-10-27

- D1-1 repo bootstrap: pyproject, Makefile, CI (pytest, ruff, gitleaks), env template.
- D1-3 receipts: hash-chained provenance log signed with the server Ed25519 ledger key (recomputed hashes without the key are rejected) plus one signed export manifest (seq, ts, head + count per run): truncation, whole-run deletion and rollback to an older export are detected (canonical JSON, redaction of e-mail/phone, `verify` checks hashes, links, timestamps and approval-before-external-write); 16 tests.
- D1-2 settings: `Settings.load()` validates the environment and fails fast (`ConfigError` names the variable): weak or judge-password-derived `SESSION_SECRET` refused (process-random fallback only when no judge login), strict booleans, https-only Model API URL, `TRUSTED_PROXY` as IP list, graph adapter needs its credentials, secrets kept out of `repr`, `.env` refused if group/other-readable; `STUDIO_READ_ONLY` kill switch (`require_writable`); thread-safe daily `Budget` whose `charge` raises `BudgetExceeded` without recording; mypy added to CI; 30 tests.
- D1-4 approvals: pending approval binds `content_sha256`, run `chain_head`, one-time nonce and issue `ts`; the browser key (registered per session, id = key fingerprint, session stored only as a hash) signs domain-separated canonical bytes; `verify_and_consume` checks action/item, content, chain head, nonce, TTL 900 s / skew 60 s and the Ed25519 signature, then consumes the nonce inside the caller's `BEGIN IMMEDIATE` transaction (two concurrent consumes: exactly one wins); 11 distinct error codes; approval receipts carry the signature and `verify(..., approver_keys=...)` checks it, requires the chain head to be an earlier receipt of the run, and ignores invalid approvals when authorising writes; 24 tests.
- D1-4 fix (security review): signed approval fields (and the signature) are exempt from PII redaction, so receipts keep exactly what the human signed (a PII-looking `item_id` used to be rewritten and break verification); the approval receipt is now written by a transactional SQLite receipt store (`studio/store.py`, `UNIQUE(run_id, prev)`, durable version counter) inside the caller's transaction, so a rollback leaves neither a consumed nonce nor a phantom approval receipt; `verify_and_consume` refuses a non-transactional ledger; ledger storage is pluggable (memory/SQLite); 10 new tests.
- D1-6 db + seed: schema for runs, receipts, ledger_meta, approvals, nonces, keys, briefs, creatives, campaigns, comments, leads, tasks, reports, sandbox_meta (documented in `docs/architecture.md`); ledger key in a 0600 PEM file (created with O_EXCL, loose modes refused, `ledger.pub` beside it); key epoch id stored in `ledger_meta` and signed into every manifest (verify rejects an epoch that is not the ledger key; reopening with another key fails closed); manifest `seq` is the durable ledger version bumped in the same transaction as each receipt write; export reads receipts and seq from one snapshot; synthetic seed only (refuses non-`@example.com` e-mails and non-`+48 000 000 xxx` phones); `reset_demo(keep_receipts=True)` keeps receipts, nonces and approver keys; 16 tests.
- D1-4 fix 2 (security review): the signed approval message holds only opaque values (internal `item_id`, `content_sha256`, chain head, approver key id, nonce, ts), so receipts store it byte-exact with no PII; `Pending.create` rejects non-opaque item ids (`invalid_item`, e.g. e-mails or phone-like ids) and the ledger refuses free text in signed approval fields; human-readable content stays in the access-controlled approvals flow, receipts only see its hash; tests: e-mail item id rejected, a seeded inbox run exports no e-mail/phone and all 5 signatures verify.
- D1-5 Muse client: OpenAI-compatible Meta Model API client on `httpx` (the installed OpenAI SDK uses `httpx2`, which respx cannot intercept) — `respond` (Responses: tools, reasoning, `previous_response_id`) and `chat` (Chat Completions); every call, including HTTP and network failures, appends a `model_call` receipt with the model id the API reports, tier + reason (tier must match the model), request/image/output hashes, usage incl. cached and reasoning tokens, and cost from the published price table; read-only and daily budget checked before the request, incurred cost always recorded; API key only in the header (never in receipts, errors or `repr`); `structured()` with strict JSON schema (closed objects, all keys required, no allOf/oneOf) and pydantic validation; vision parts with magic-byte MIME check and 50 MB cap; cassettes recorded from 5 real calls (headers never stored), `make smoke-live` makes one strict call and prints usage only; 22 tests.
- D1-5 fix (security review): image input hashes are computed before the request is sent, only at the known part positions (`image_url.url`, `input_image.image_url`/`file_id`), and never raise (malformed data URLs get an `undecodable:` marker, remote URLs a `url:` hash); every attempted call writes a receipt — success, or an error receipt for network, HTTP, malformed response body or abort; response shapes are validated; 4 tests.
- D1-7 app skeleton: FastAPI `create_app(settings)` (lazy `studio.app:app`); public read-only `/` (receipt table, autoescaped), `/healthz`; `POST /login` with the attempt reserved in a bounded, locked limiter before the body is read (5 per 15 min per client, cleared on success), bytes constant-time compare (non-ASCII → 401); HMAC session cookie from the dedicated `SESSION_SECRET` plus server-side revocation, HttpOnly + SameSite=Lax + Secure, 8 h; `POST /logout` only; `_client_ip` uses the rightmost `X-Forwarded-For` entry only when the peer is a `TRUSTED_PROXY`; `POST /api/keys` (session, same-origin, read-only → 503, max 5 keys per session); `GET /api/receipts.jsonl`, `/api/ledger-manifest`, `/api/ledger-key`, `/api/approver-keys`; 64 KiB body cap (413, also for chunked bodies); CSP and security headers; 27 tests.
- CLI: `studio verify <file>` with `--server` (fetches ledger key, latest manifest seq and approver keys over https; TLS verified), or offline `--key`/`--key-file` + `--approver-keys` + `--min-seq`; refuses to run without an approver registry unless `--skip-approver-signatures`; prints `chain OK, N receipts, M signatures valid` or every failing receipt id; README documents verification; 6 tests.
- D1-7 fix (security review): approver keys are bound to the login session — they expire with it, logout revokes them, a restart revokes all (sessions are in process memory), and `verify_and_consume` rejects inactive keys (`key_inactive`); revoked keys stay published so earlier approvals remain verifiable (deliberately not deleted). Login limiter keys IPv6 by /64 and IPv4 by /32, adds a global judge-account failure budget (20 failures from any addresses → lockout with exponential backoff, in-flight attempts counted), never evicts blocked prefixes and refuses new clients when the table holds only blocked entries; 10 tests.
