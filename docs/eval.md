## 1. Tamper suite (`studio verify`)

Each case is a fresh ledger (random number of receipts, a signed reply approval, its adapter step and its write, a second run, and a third run with a confirmed Brief v1 and a campaign approval that signs its `brief_sha256`), exported and then tampered with. Verified with the ledger key, the approver registry and, for rollback, the latest known manifest seq. "The server itself" rows are logs signed with the real ledger key: what verify still catches if the server lies.

## 3. Reviewer catch rate (seeded bad ads)

P9 (no official-service or company-registration claims, no absolute tax/legal promises) and the unfilled-`[FACT]` rule (the copywriter may not invent a fact; an unfilled placeholder cannot be signed) come from those cases.
